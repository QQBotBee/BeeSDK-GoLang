# Bee API 105-106 Go SDK Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with review checkpoints.

**Goal:** Synchronize the two APIs defined in `e.txt` (opcodes 105 and 106) into the Go SDK, its public wrappers, and API documentation.

**Architecture:** Extend the existing single-file SDK in `bee_sdk.go`: add opcode constants and names, implement `RobotContext` methods beside the other API wrappers, and expose the same operations through `BeeAPI`. Reuse `Call` for string results and parse opcode 106's numeric result with `strconv.Atoi`, preserving IPC errors and reporting malformed numeric responses.

**Tech Stack:** Go 1.22, standard library `strconv`, existing SDK IPC transport, Markdown documentation.

## Global Constraints

- Preserve Windows/386 assumptions and the existing IPC command format.
- Do not change unrelated message, lifecycle, or transport behavior.
- Keep `e.txt` unmodified; it is the source snapshot for this sync.
- Use TDD locally: tests must fail before production implementation, then pass.
- Do not commit `*_test.go` files, per the existing repository workflow.

```go
func (ctx *RobotContext) TextImage(pathOrURL string) (string, error) {
	return ctx.Call(OpTextImage, pathOrURL)
}

func (ctx *RobotContext) GetGroupMessageSenderIdentity(robotID string) (int, error) {
	out, err := ctx.Call(OpGetGroupMessageSenderIdentity, robotID)
	if err != nil {
		return 0, err
	}
	identity, err := strconv.Atoi(out)
	if err != nil {
		return 0, fmt.Errorf("解析群消息发送人身份: %w", err)
	}
	return identity, nil
}
```

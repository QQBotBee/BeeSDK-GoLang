# Bee API 105-106 Go SDK 同步设计

## 目标

将 `e.txt` 新增的两个易语言 SDK 接口同步到 Go SDK，并保持现有操作码、`RobotContext`、`BeeAPI` 和 API 文档的一致性。

## 接口映射

| 操作码 | 易语言接口 | Go 常量 | `RobotContext` / `BeeAPI` 方法 | 返回值 |
| --- | --- | --- | --- | --- |
| 105 | `文本_图片` | `OpTextImage` | `TextImage(pathOrURL string)` | `(string, error)` |
| 106 | `取群消息发送人身份` | `OpGetGroupMessageSenderIdentity` | `GetGroupMessageSenderIdentity(robotID string)` | `(int, error)` |

`TextImage` 原样传递图片本地路径或网络链接，并返回框架生成的图片文本代码。`GetGroupMessageSenderIdentity` 原样传递机器人标识，将框架文本返回值解析为整数；`0` 表示群成员，`1` 表示管理员，`2` 表示群主。

## 实现边界

- 在操作码常量区加入 `105` 和 `106`，并同步 `OpcodeNames`。
- 在 `RobotContext` 上实现底层调用方法。
- 在 `BeeAPI` 上提供对应的链式便捷方法。
- 更新 README 和 API 参考中的支持范围、示例及操作码表。
- 不修改 IPC 协议、消息发送逻辑或现有接口行为。

## 错误处理

`TextImage` 直接返回 IPC 调用错误。`GetGroupMessageSenderIdentity` 在 IPC 调用失败时返回该错误；框架返回非整数文本时返回整数解析错误，不把无效值静默映射为普通成员。

## 验证

- 先用测试验证两个操作码、参数顺序、返回值和整数解析错误。
- 运行 `gofmt`。
- 运行 `go test ./...` 和 `go vet ./...`。
- Windows/386 DLL 构建不属于本次接口映射的必要验证，但保留现有 Windows/386 兼容性。
